## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> POST /api/demo/switch | Anyone who finds the URL can call it |
| Render preDeploy -> database | Seed writes accounts with a shared password |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13-01 | Elevation of privilege | Switch enabled on a non-demo deploy | high | mitigate | Route returns 404 unless `DEMO_MODE === "true"` (strict); unit tests cover unset, "", "false", "TRUE", "1"; switcher rendered server-side only; no NEXT_PUBLIC flag |
| T-01-13-02 | Spoofing | Login CSRF forcing a victim into a seeded account | medium | mitigate | Origin must equal the configured app origin; missing or foreign Origin -> 403 (unit and live tests) |
| T-01-13-03 | Elevation of privilege | Switching into arbitrary accounts | high | mitigate | Zod enum of three roles mapped to a fixed allowlist of seeded emails; anything else -> 400 |
| T-01-13-04 | Information disclosure | Seed password leakage | medium | mitigate | Password only in env (`sync: false`); seed and route never log it; 500 path hides error messages |
| T-01-13-05 | Spoofing | Anyone on the public demo URL can become the seeded judge | medium | accept | Required by AUTH-04 for the hackathon demo; seeded accounts hold sandbox data only; non-demo deploys set `DEMO_MODE=false` |
| T-01-13-06 | Repudiation | Stale session after switching | low | mitigate | Switch signs out the current session first; live test asserts the old cookie gets 401 |
</threat_model>
