<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> pages and /api/me | Session cookie decides what data is shown |
| internet -> /api/health | Unauthenticated endpoint |
| worker -> Postgres | Worker writes with the shared DATABASE_URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03-01 | Elevation of privilege | /dashboard and /api/me without a session | medium | mitigate | `getActor()` in the page and route; redirect to /login or 401; `proxy.ts` is only an optimistic redirect |
| T-01-03-02 | Information disclosure | /api/me returning other users | medium | mitigate | Returns only the session user's own fields; no id parameter accepted |
| T-01-03-03 | Information disclosure | /api/health | low | accept | Exposes only db ok, worker age and the commit SHA of a public repo; no versions or env values |
| T-01-03-04 | Denial of service | Worker crash loop unnoticed | low | mitigate | Heartbeat age shown on dashboard and health; SIGTERM graceful stop |
| T-01-03-05 | Spoofing | Judge code entered in the browser | low | mitigate | Code is sent only as the `x-judge-signup-code` header to the same origin and checked server-side (plan 01-02) |
</threat_model>
