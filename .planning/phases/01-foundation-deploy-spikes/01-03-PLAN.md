## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scripts -> committed evidence files -> public GitHub | Spike output written by every later plan is published |
| env -> error messages | Invalid env values could leak through parse errors |
| smoke tests -> live database | Smoke runs create real accounts on the deployed app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03-01 | Information disclosure | Evidence files (`writeEvidence`, `check-evidence`) | high | mitigate | Key-based and value-based redaction, signed-URL query stripping, `assertNoSecrets` before every write, `check-evidence` gate that prints file names only; unit-tested in `redact.test.ts` |
| T-01-03-02 | Information disclosure | Env parse errors | low | mitigate | `getEnv()` errors list key names only, never values |
| T-01-03-03 | Tampering | Throwaway smoke accounts on the live database | low | accept | Accounts use `@smoke.example.com`, worker role only, sandbox PayPal emails; no money moves in Phase 1 |
</threat_model>
